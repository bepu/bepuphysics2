# AosBaselines

Investigatory harness measuring how much the AoSoA (`Vector<T>` bundle) collision testers actually buy over a well-optimized scalar AoS representation, using scalar reference ports that are **bitwise identical** per lane to the wide implementations.

Ported so far: sphere-sphere, sphere-capsule, sphere-box, sphere-triangle, sphere-cylinder, sphere-hull, box-box, box-triangle, cylinder-cylinder, convex hull-convex hull, capsule-hull, box-hull, cylinder-hull, and triangle-hull (including a scalar port of the DepthRefiner's witness variant, generic over scalar support finders with margin support for the point/segment-plus-margin cases).

## Usage

```
dotnet run -c Release --project AosBaselines -- [fuzz|bench|all] [--count N] [--seed S]
```

- `fuzz`: generates `N` cases per pair type (default 4,000,000) and verifies bitwise equality of every observable manifold field between the wide tester (run on full bundles) and the scalar port (run per lane). Nonzero exit code on any mismatch; mismatches print full bit-exact input reproductions.
- `bench`: measures ns/pair for both paths on identical data across a matrix of {hot, streaming} working sets × {mixed, contact-heavy} workload profiles.

## Case generation

`CaseGenerators.cs` mixes purely random poses with *feature-informed* placement: a contact normal is drawn from the shapes' feature sets (face normals of either box, edge-edge cross products, vertex directions), then the shapes are placed by support-point matching with a controlled separation (deep/moderate/hairline penetration, exact touch, hairline separation, speculative-margin boundary, miss) and a tangential slide that walks the contact across faces toward edges, corners, and off the shape. Orientation categories include exact identity, shared orientations (all edges parallel — degenerate cross products), exact quarter-turn alignments (ties in face selection), epsilon perturbations of all of those, and 45° tilts. Shapes include cubes, extreme plates, and extreme rods. Coincident centers and zero-margin cases are included.

Verified coverage (from the fuzz summary): all contact counts 0–4 occur with meaningful frequency, and contacts originate from both the box-A-vertex and face-B-edge codepaths.

## Bitwise mirroring rules

The scalar ports (`ScalarMath.cs`, `SpherePairScalarTester.cs`, `BoxPairScalarTester.cs`) reproduce the wide code operation-for-operation. Rules discovered/used, important when porting more testers:

- Preserve exact operation order; IEEE float addition is not associative. RyuJIT does not auto-contract to FMA or reassociate, so a faithful transliteration is bitwise exact.
- ~~`Vector.Min/Max` lane semantics are `(a OP b) ? a : b`~~ **SUPERSEDED (2026-08-14): on .NET 10, `Vector.Min/Max` carry IEEE minimum/maximum semantics — bitwise identical to `MathF.Min/MathF.Max` including ±0 ordering and NaN payload propagation (see the `minmaxprobe` mode). The exact mirror is `MathF.Min/Max`; `float.MinNative/MaxNative` keep the old maxss-style semantics and diverge at ±0 and NaN-in-second-operand.** `MinNative/MaxNative` remain acceptable only where operands provably exclude those inputs (length-squared comparisons and the like); the pre-hull-pair testers still use them and are fuzz-clean but latent. Discovered via capsule-hull's exact-±0 segment supports (see the hull pair port notes).
- Do not use `Vector3.Dot`/`Length` intrinsics for mirrored math; their summation order is not guaranteed to match the wide helpers. Componentwise `Vector3` operators (`+`, `-`, `*` by scalar) are safe. **Exception — self-dots**: `Vector3.LengthSquared()`/`Dot(v, v)` are safe. The intrinsic's pairwise tree (`(x²+y²)+(z²+0)`, whether lowered to shuffles or `vdpps` with excluded lanes forced to +0) differs from the linear sum only at negative-zero partial sums, and squares can never be −0 — and the intrinsic form collapses the extract/mulss/addss chain to one instruction (refiner step 9).
- `Vector.AndNot(a, b)` is `a & ~b`.
- `MathF.Sqrt`/`MathF.Abs` match `Vector.SquareRoot`/`Vector.Abs` bitwise (correctly rounded / sign-bit clear).
- `Vector.ConditionalSelect` chains become nested ternaries/branches; comparisons involving NaN are false in both forms, which keeps select behavior identical.
- Bundle-level shortcuts in the wide code (`SquishMaximumContactCount`, the all-lanes-miss early out, partial-bundle masking) only skip work that is masked out per lane, so they need no scalar counterpart.
- The DepthRefiner freezes per-lane state on termination (its `terminatedLanes` masks gate every write), so per-lane results are bundle-independent and a scalar loop that stops at its own lane's termination is bitwise identical. One subtlety: a lane that terminates at the edge-distance check inside `GetNextNormal` still receives that call's feature/weight updates (the selects were masked with the pre-check state); the scalar port must do the same.
- Code that is already scalar-per-slot in the wide tester (hull support finding, `PickRepresentativeFace`, hull contact generation, the scalar `ManifoldCandidateHelper.Reduce`) is copied nearly verbatim — including its `Vector3.Dot` intrinsic calls, which must *not* be replaced with the ordered mirrors since the goal is to match what the wide path actually executes.
- Comparisons are gated on observability: contact fields only compared where the exists flag is set, normal only when at least one contact exists (matching `ReadFirst` semantics). Exists flags themselves are always compared.

Result: zero mismatches over ~20M fuzzed lanes per configuration across multiple seeds, including partial bundles.

## Benchmark methodology notes

- Wide inputs must be **aligned** (the harness uses 64-byte-aligned native allocations, matching the engine's BufferPool behavior). Managed arrays are only 8-byte aligned, which makes cache-resident wide benchmarks noisy and unfair: 32-byte `Vector<float>` loads randomly straddle cache lines depending on allocation luck.
- Wide/scalar trials are interleaved so frequency/thermal drift affects both paths equally; short benchmark sections that run right after process start otherwise measure pre-ramp clock speeds. Prefer min-based statistics.
- Warmup is time-based (≥2s of alternating invocations per section): .NET's call counting toward tier1 doesn't start until ~100ms of activity, and dynamic PGO adds an instrumented stage plus background compilation, so a fixed small invocation count leaves early trials on tier0/OSR/instrumented code. With the 2s warmup, medians collapse onto mins — much of the "thermal noise" seen with short warmups was actually mid-section tier promotion.
- JIT-mode sensitivity was checked by running both default tiered+PGO (2s warmup) and `DOTNET_TieredCompilation=0` (full-opt upfront, no dynamic PGO). Ratios agree within ~±0.2x everywhere; dynamic PGO gives the branchy *scalar* paths a small relative boost in most testers (sphere 6.7x vs 7.1–7.6x, box 2.24x vs 2.55x, cylinder 2.15x vs 2.36x contact-heavy), while hull stays in its ~0.8–1.05x parity band in every mode. The tiered+PGO numbers are the representative ones for real engine runs.
- The workload's contact rate matters a lot: the scalar path early-outs per pair, while a wide bundle only early-outs when *all* lanes miss. Mixed (~28% contact) flatters AoS; contact-heavy (~69%) approximates a post-broadphase workload.

## Baseline results (8-lane AVX2, WSL2, 2026-08-10)

ns/pair by min over interleaved trials, measured 2026-08-11 on an idle machine (tiered+PGO steady state, 2s warmups; medians matched mins within a few percent). Earlier sessions with background load inflated absolutes up to ~3x but left ratios within ~±20%.

**Codegen audit update (post-antipattern fixes):** a full-opt disasm audit of the scalar kernels found the dominant antipattern was mixing componentwise *field* access with RyuJIT's SIMD-promoted `Vector3` locals — ~24 `vinsertps` + ~14 extract shuffles + ~15 spill moves per sphere-box pair — plus xmm↔gpr round-trips in the bitmask selects. `ScalarMath` was rewritten in promotion-friendly forms (whole-`Vector3` operator transforms, ordered-reduce SIMD dots, shuffle-based cross, `vblendvps` selects, constructor-built matrix rows), all bitwise-identical (re-fuzz verified). Effects: sphere-triangle scalar 37→26 ns (ratio 5.8x→**3.1x**), cylinder-cylinder scalar 1485→1009 ns (contact-heavy ratio 2.9x→**2.1x**; mixed **1.34x**), hull-hull scalar improved to **0.81–1.08x** (AoS wins large-hull and miss-heavy configs), sphere-hull mixed at **0.96x parity**. Box-box was unchanged (~2.0–2.4x) — its cost lives in tester-body scattered code, which needs the packed treatment to move. The table below predates these fixes except where noted; ratios above are the current state.

**Box-box hillclimb (disasm-guided, 2026-08-11):** full-opt disasm of the box-box scalar path exposed a different dominant pathology from the small testers: `Test` compiled to a single 14KB method that **exhausted RyuJIT's inlining budget**, at which point even `Vector3.op_Subtraction` stopped expanding as an intrinsic and became a real call with struct-return ABI (as did `ScalarMath.Min/Max` and the `AggressiveInlining` phase helpers). Under `TieredCompilation=0` this ran at 872 ns/pair — dynamic PGO was partially rescuing it to ~282. Fixes, applied iteratively with re-disasm + fuzz between steps (all bitwise-preserving, 0 mismatches over ~15M box-box lanes):
1. **Phase split**: SAT into a non-inlined `TestSat`, `CreateEdgeContacts`/`AddBoxAVertices` explicitly `NoInlining` — each phase gets a fresh inlining budget, so operators expand again (TC=0 collapsed 872→235 ns).
2. **Whole-vector normal plumbing**: `TestEdgeEdge` outputs a `Vector3` built once and blended whole (`vblendvps`), replacing componentwise out-floats/selects; whole-vector `Negate`/`Abs` (sign-bit xor/and, bitwise identical to `-x`/`MathF.Abs`).
3. **`CandidateAos` = 16 bytes → one-blend `SelectCandidate`**; `Reduce` code shrank 1780→1050 bytes.
4. **Bounds-check elimination** on the candidate buffer (`MemoryMarshal.GetReference` + `Unsafe.Add`, counts provably ≤ 8).
5. **Mask-based selects** (`LessMask`/`GreaterMask`/`EqualMask` + `Select(mask, ...)` in `ScalarMath`): conditions computed with `vcmpss` stay in the SIMD domain, removing the `ucomiss+cmov+movd` gpr↔xmm crossing per select. Also removed store/reload round-trips through out-param byrefs in `TestSat`.
6. **Packed `TestEdgeEdge`**: the three structurally-identical axis blocks live in lanes 0–2 of `Vector128` values (one `sqrtps`+`divps` instead of 3 scalar sqrt+div; per-lane operand order matches the scalar blocks exactly, and sqrt/div/mul/add are lane-wise bit-identical, so bitwise equality holds by construction).
7. **Packed edge clipping**: the 4 distance dots per clip invocation transpose into lanes; both plane normals reuse the transpose; min/max/select lanes preserve scalar operand order. Measured a wash on wall-time but kept (smaller code, fewer ops).

Net: scalar box-box **207.6 → ~120 ns/pair mixed (-42%), 281.8 → ~200 ns/pair contact-heavy (-29%)** on a clean machine, dropping the AoSoA ratio from 2.2x/2.5x to **~1.3–1.4x mixed / ~1.6–1.8x contact-heavy**. The `AsVector128Unsafe` (skip W-zeroing) variant of the dot helpers measured as a wash vs the zero-extending form, so arithmetic ops keep the safe zero-extend; bitwise-only ops (selects/negate/abs) use the unsafe reinterpret. Lesson: on big testers the JIT inlining budget is the first-order antipattern (watch for operator intrinsics degrading to calls in disasm); componentwise plumbing and select domain-crossings are second-order; packing structurally-parallel sub-blocks is the remaining lever and stays bitwise-safe when per-lane operand order is preserved.

**Portability pass (same day):** `ScalarMath` and the box tester now use only the portable `Vector128` generic API — no `Sse`/`Sse2`/`Sse3`/`Sse41` references remain (`ConditionalSelect` for blends, `Vector128.LessThan`-family broadcast compares for masks, `Vector128.Shuffle` with constant indices, `Vector128.Sqrt`, `MinNative`/`MaxNative` for the minss/maxss `(a OP b) ? a : b` semantics), so the harness transports to ARM/NEON cleanly. Disasm confirms every generic op lowers to a native instruction on x64 (packed `TestEdgeEdge`: 1 `vsqrtps`, 1 `vdivps`, 16 shuffles, 7 `vorps`, zero BCL calls) and wall time is unchanged. Two-vector shuffles (unpack/movlhps) have no generic equivalent; where the SSE version used them (candidate-normal assembly, the packed clip's transpose), the replacements are single-vector shuffle + or merges over deliberately zeroed lanes — or-with-zero is bit-exact — and the packed clip (which had measured as a wash) reverted to its simpler portable form. Remaining scalar face-test chains in `TestSat` also collapsed into whole-`Vector3` expressions: the three face-A depths are literally one `Vector3` expression whose per-lane associativity matches the componentwise original, and face B builds the transposed abs-rotation columns with shuffle+or merges to do the same. The only remaining platform-specific code in the project is `SphereBoxScalarTesterPacked` (an explicitly x64 experiment).

**Helper audit (same day):** each remaining `ScalarMath` helper was tested for redundancy by substituting its BCL/engine equivalent and letting the fuzzer rule. Results: `Cross` → `Vector3.Cross`, `CreateFromQuaternion` → `Matrix3x3.CreateFromQuaternion`, and `Transform` → `Matrix3x3.Transform` were bitwise-clean across the suite — **deleted as cruft**, call sites now use the equivalents directly. `Dot`/`Length`/`TransformByTransposed` are **proven load-bearing**: substituting `Vector3.Dot` produced 2287–12115 box-box and 875–3160 cylinder-cylinder mismatches per ~1.9M lanes (its reduction order differs from the wide `(x+y)+z`; the divergence surfaces on the degenerate/axis-aligned inputs those fuzzers emphasize — sphere and hull configs never caught it, a warning about how quietly this class of bug can hide). `Min`/`Max`: the `MathF.Min/Max` substitution *passed* fuzz (the corpus never reaches the NaN/±0 divergence inputs); the semantics argument (documented `Vector.Min` difference) plus codegen (`minss` is one instruction; `MathF.Min` is a fixup sequence) favors native min/max — and since .NET 9's `float.MinNative`/`MaxNative` expose exactly that as a scalar intrinsic, the helpers were later deleted entirely in favor of direct `float.MinNative`/`MaxNative` call sites (fuzz-clean, bench-neutral). The Vector3-returning helpers (`Select` x2, `TransformByTransposed`) were also converted from `out` parameters to value returns: Vector3 is a SIMD type returned in a register, so the value form has no byref for the JIT to undo when keeping destinations enregistered (`out` relies on inlining + promotion analysis succeeding every time). Fuzz-clean; the first idle-machine benchmark after the change produced the session's best contact-heavy reading (182.9 ns min, ratio 1.63x; mixed 119.6 ns, 1.26x) — consistent with a small real win in the select-dense contact path, though within the noise band's edge. `MultiplyByTranspose` keeps `out` deliberately: a 36-byte Matrix3x3 return goes through a hidden memory buffer at any real call boundary, so `out` is the honest form for matrix-sized results (matching the engine's own convention). `MultiplyByTranspose` (`a·bᵀ`) and `TransformUnitXY` have no scalar engine equivalent (`Matrix3x3.MultiplyTransposed` is `aᵀ·b`). Select/mask helpers keep their earlier measured justification. Post-deletion: 19/19 fuzz configs clean at 4M cases, box-box unchanged (~127-132 mixed / ~196-198 contact-heavy on an idle machine).

**Hillclimb round 2 (same day):** five candidate optimizations measured individually against the ~±5ns machine noise floor; evidence decided what stayed. (1) **Vectorized `Reduce`** (gather candidate components into lanes, horizontal argmax/argmin with first-index-of-equal tie-breaking — bitwise-equivalent by construction and fuzz-verified): **regression, +20 ns/overlapping pair** — the 24-element gather plus fixed 8-lane work costs more than the short serial chains at typical candidate counts. Reverted; the analysis (NaN-freedom via the depth recompute, first-strict-max == first-equal-index) is preserved here for a future relaxed-equality variant. (2) **Branchless candidate appends** (9th trash slot, unconditional store, count advanced by the exists flag as a byte — mirrors the wide masked stores): wash; initially kept, later removed — a wash does not justify the trash-slot machinery and flag reinterpretation over the plain branchy form, which is what stands. (3) **Transpose-once prologue**: `MultiplyByTranspose` and the offset/representative-face dot groups rewritten as `Matrix3x3.Transpose` + broadcast-row sums (per-component operand order and associativity identical to the ordered dots — bitwise verified): **~2-4 ns on every pair**; kept. (4) **Index-tracking select chains in `Reduce`** (track the winner's index as a float in the SIMD select domain, copy the 16-byte winner once at the end instead of blending it every iteration): wash; kept as strictly less work. (5) **Rejection early-outs in `TestSat`** — the SAT depth is a running minimum, so once below `-speculativeMargin` the reject decision is final and the normal is discarded; bailing after the edge phase and face-A phase is **bitwise-output-equal** and bought **~8-10 ns on the mixed profile** (114.7-122 ns, ratio ~1.28x); contact-heavy unchanged as expected. This is the structural AoS per-pair early-out advantage made concrete: the wide path can only skip when the whole bundle misses.

**Noted result-changing opportunities (not taken; would break bitwise equality):** (a) **FMA contraction** — RyuJIT never contracts mul+add; explicit fused ops would cut arithmetic roughly in half through the dot/transform/SAT/clip paths *on both the scalar and wide implementations* and be more accurate (single rounding), making it the largest and most symmetric win available; (b) **normalization-free SAT** — comparing `depth*length` products algebraically instead of dividing by axis lengths would eliminate the sqrt+div per edge-axis block; (c) **`Reduce` heuristic relaxation** — the four-pass argmax structure with exact tie-breaking and the extremity bias is inherently serial; loosening tie semantics unlocks the packed reduction that lost under bitwise constraints; (d) **cold-branching the degenerate-axis guards** (1e-7/1e-15 fallbacks) instead of blending them; (e) *bitwise-legal but sub-noise*: fusing the depth pass into candidate generation (same formula, same inputs, one less pass).

**FMA characterization (`BoxPairScalarTesterFma` + `fma` mode):** a non-bitwise variant with explicit fused ops at the natural sites (scalar fma-chain dots, broadcast-row transforms, packed SAT accumulations, face depth chains, raycasts, Reduce arithmetic) plus the known-risk sites on purpose (asymmetric fused signed-area determinants and cross products). Compared against the wide reference with structural categorization + ulp statistics over 8M lanes:
- **Performance: ~nothing.** 1.00x mixed / 1.03-1.04x contact-heavy vs the bitwise scalar; the wide advantage barely moves (1.63x vs ~1.7x). The earlier "FMA halves the arithmetic" estimate was wrong for this tester: box-box is bound by latency chains, selects, branches, and structure — not FP-throughput — so removing add uops doesn't shorten what the pipeline actually waits on. (FMA may still pay on genuinely throughput-bound kernels — the refiner's support loops, or the wide implementations themselves — but that's unmeasured.)
- **Structural divergence: the real cost, and it's discrete, not smooth.** On the (deliberately tie-heavy, degeneracy-heavy) fuzz distribution: mixed 2.4% of lanes diverge structurally (0.54% accept/reject flips, 0.46% contact pattern changes, 1.42% feature id changes), contact-heavy 7.4% (2.10% / 1.78% / 3.54%). Amplifiers are the comparison boundaries: SAT winner ties between near-equal axes, normal calibration sign at `dot ≈ 0`, the clip parallel-guard at `|velocity| ≈ 1e-15`, and the speculative margin accept boundary. These rates are upper-bound-ish — the fuzzer deliberately samples ties that real pose distributions visit rarely (but not never).
- **Numerical drift where structure matches: overwhelmingly tiny, with a fat tail.** Normal components within 2 ulp for ~96-97% of samples, offsets within 16 ulp for ~93-96%; means (normal 4e-3, offset 6e-3 mixed) are dominated by a ~1% tail reaching O(1) errors — mostly same-feature-id calibration sign flips (max normal error 2.0 = fully negated normal) and clip-guard flips throwing speculative contact positions (offset max 1e3). Depth's poor-looking ulp buckets (47% within 2 ulp in contact-heavy) are a metric artifact: depths cluster near zero where ulp distance is hypersensitive; the absolute error mean is 2e-4.
- **Net read:** for box-box, FMA is (approximately) all determinism-cost and no perf-payoff. If FMA is ever adopted it should be motivated by a throughput-bound kernel and treated as a versioned, both-paths (scalar+wide) semantic change, with the determinant/cross sites either left unfused or compensated — they convert ulp noise into sign flips near zero by construction.

**Wide-dot alignment to `Vector3.Dot`: explored, verified, declined.** The `dotprobe` mode establishes empirically that `Vector3.Dot`'s lowering reduces as the pairwise tree `(m0 + m1) + (m2 + 0)` (the zero-extended W lane participates in the horizontal add), stable across compilation tiers, and diverging from the wide linear `(m0 + m1) + m2` **only at negative-zero partial sums** (`-0 + +0 = +0`; all rounding-sensitive probes agree). Necessity of the fourth zero term was verified three ways: the probe eliminates every zero-free parenthesization of three terms; the linear-engine + `Vector3.Dot`-scalar combination produced thousands of box/cylinder fuzz mismatches; and patching `Vector3Wide.Dot` to `x*x' + y*y' + (z*z' + Vector<float>.Zero)` made the full suite bitwise-clean over 8M+ lanes with the scalar side on plain `Vector3.Dot` (wide throughput unaffected; the `Length` family needs no change since square sums cannot be -0). The engine change was then **reverted by choice**: the non-removable `+ Vector<float>.Zero` is a maintainer trap (it reads as deletable dead code), spends an add in every engine dot to serve a test harness, and ties the engine's canonical order to an unspecified JIT lowering detail (`Vector3.Dot`'s tree is deterministic per runtime version × ISA but undocumented, and has changed historically). The scalar side keeps the explicit ordered-reduction mirrors (`ScalarMath.Dot`/`Length`/`TransformByTransposed`) as the cheaper place to carry the ordering contract; hull's per-slot verbatim regions keep `Vector3.Dot`, now including the `Reduce` depth dots that match `ManifoldCandidateHelper`'s own `Vector3.Dot` calls. A middle path exists if ever wanted: a "bitwise modulo zero sign" comparison level would likely admit plain `Vector3.Dot` scalar-side with no engine change (the divergence class appears to stay confined to zero signs through the guarded testers), but that relaxation was not adopted.

**Bitwise-legal branchy specialization: legal, and measured unprofitable (all reverted).** Following the principle that bitwise equality constrains outputs rather than control flow, six specializations were built and fuzz-proven bit-identical: branch-specialized face selection (each arm the straight-line collapse of the select chains for a known winner), skipping the vertex raycast phase when the edge phase fills the candidate buffer, construct-inside-the-branch candidate appends, a scalar-args `AddContactsForEdge`, and a count-1 fast path through `Reduce` (with a small proof that the distance and signed-area passes provably never select). Measurement killed all of them: the append/signature batch cost ~30 ns/pair contact-heavy (~225 vs the ~183-195 band), and bisection showed the regression was shared between the data-dependent append branches and the 12-scalar-argument call signature (argument spills at four call sites); the face-selection branches first measured as a wash, then two independent min-statistics readings under intermittent load placed them at ~212, also a regression — the winning face varies per pair in contact-heavy workloads, so the branch is a per-pair coin flip and mispredicts swamp the ~20 saved ops. Everything reverted; the appends subsequently settled on the plain branchy form (the branchless blind-store variant's one clean A/B was a wash, and a wash doesn't pay for a trash slot and a reinterpreted-bool count bump). Final state re-fuzzed clean. The conclusion worth keeping: on this tester the faithfully-mirrored data-parallel shape *is* near the scalar optimum — the profitable control-flow divergences were the coarse, monotone ones (rejection early-outs), not fine-grained branch specialization. Measurement-method note (corrected): the day's contamination was thermal — sustained AVX benching depletes the laptop's turbo budget, so later trials/sections run monotonically deboosted. That defeats min-statistics (if the whole tail is deboosted, the min is inflated too); it does NOT defeat ratios, which the wide/scalar trial interleaving keeps honest under any smooth clock drift (the day's ratios held 1.6-1.8 throughout). Treat ratios as the thermally-robust metric; trust absolutes only when the wide side's min lands in its known band. The `--cooldown <ms>` flag duty-cycles trials (sleep between trial pairs, longer recovery after warmup) to keep measurements in the boosted regime; disabling turbo at the OS level (max processor state 99%) is the gold-standard alternative — stable clocks at base frequency.

**Cleanup pass (same day):** three further de-pessimizations, measured individually. (1) Deleted the `ScalarMath.Negate`/`Abs` wrappers — `-v` and `Vector3.Abs` are already JIT intrinsics emitting the identical `vxorps`/`vandps`; wrapping an intrinsic in an SSE special case is pure ceremony. (2) Dropped `in` from every *inlined* helper's struct parameters (tester helpers and all of `ScalarMath`): an `in` byref takes the argument's address, which address-exposes the caller's enregistered SIMD locals; by-value copies are elided after inlining. `in` initially remained on the phase-method call boundaries, but a later pass (prompted by the observation that byref args force the *caller's* SIMD locals addressable whether or not the call inlines) removed both the `in` parameters and the `NoInlining` attributes from all phase methods: the phases are large enough that the JIT keeps them as calls by default — preserving the per-phase inlining budget with no attribute (full-opt disasm confirms zero operator-intrinsic degradation) — while dynamic PGO regains the freedom to inline a phase where the profile justifies it. Compiled code shrank (`AddBoxAVertices` 1158→924 bytes) at wash wall-time; `in` now survives only on the public `Test` signature and the 36-byte `Matrix3x3` argument, where byref genuinely avoids a large copy. (3) `AggressiveInlining` A/B: stripping every hint from the box tester measured equal-to-slightly-better (best contact-heavy readings of the session, ~191 ns) — under TC=0 the JIT then chooses *not* to inline `TestEdgeEdge` (742 B, called 3x from a 1905 B `TestSat` instead of one 5700 B blob), and its per-site decisions (plus PGO) match or beat blanket force-inlining now that no single method threatens the budget. The box tester keeps no hints; `ScalarMath`'s hints stay (stripping them was a wash on box-box, and other testers' kernels weren't re-measured against the change). All three changes bitwise-clean across the full 19-config fuzz suite.

**Box-triangle port (2026-08-12):** `BoxTriangleScalarTester` is an op-for-op scalar twin of the engine's `BoxTriangleTester` (the two-orientation `Test` overload; the others throw). Port notes, i.e. the order-sensitive facts that had to be preserved:

- **The SAT running-depth combiner is `Vector.Min`, not a select.** All four wide `Select` variants update the normal via a `depthCandidate < depth` blend but the depth via `Vector.Min(depth, depthCandidate)` — unlike box-box, which selects both. These differ at `(+0, -0)` pairs; the scalar port uses `float.MinNative(depth, depthCandidate)` verbatim. Worth adding to the mirroring rules: check *each* tester's combiner — the same-named helper differs between testers.
- **Swizzled out-params in the edge-edge helper.** `TestBoxEdgesAgainstTriangleEdge` routes the inner helper's (X, Y, Z) normal outputs into `(.X,.Y,.Z)`, `(.Y,.X,.Z)`, and `(.Z,.X,.Y)` for the A.X/A.Y/A.Z blocks; the scalar port hand-applies the swizzles: normals `(0, eZ·il, -eY·il)`, `(eZ·il, 0, -eX·il)`, `(eY·il, -eX·il, 0)`.
- **The calibration sign rides the dividend**: `inverseLength = (calibrationDot < 0 ? 1 : -1) / length`, kept literally (bitwise-equal to negate-after for finite lengths, but zero cost to keep the source form).
- **The triangle-face SAT candidate uses the calibrated normal while its depth uses the uncalibrated one**; the backface `normalDot` (also the 0.999999 face-flag test input) dots against the *uncalibrated* unit normal.
- **Count-dependent clip exists masks**: `minExists` tests `candidateCount < 6` before the min append, `maxExists` after it; the branchy scalar append sequencing reproduces this naturally. The clip epsilon is the raw `1e-5f` (t-space is normalized) — *not* scaled by epsilonScale, unlike box-box's `epsilonScale * 1e-5f`.
- **`FeatureId0 += 32768` (`MeshReduction.FaceCollisionFlag`) is applied unconditionally** when `normalDot >= 0.999999`, even if contact 0 doesn't exist; contacts are relative to A's center with no world offsetB re-add (localTriangleCenter already carries it), and `Reduce`'s inverse is a bare `1f / dot(boxFaceNormal, localNormal)` (no abs/negate, unlike box-box).
- The per-lane rejection (`nondegenerate & normalDot >= -1e-2 & depth >= -margin`, plus the active-lane mask) produces zero candidates → all-false exists through `Reduce`, so the scalar all-false early return is observably identical; the box-box-style mid-SAT depth early-outs (after the edge phase and the face-A phase) were added on the same running-minimum argument and fuzz-verified.
- `Reduce` is byte-identical to `BoxPairScalarTester`'s scalar mirror (same wide helper); it's duplicated because that file is frozen.

**Step 9, refiner square-sum intrinsics (2026-08-13, Ross-prompted):** the hillclimb's refiner steps were structural and left the arithmetic bodies alone — `ScalarDepthRefiner.LengthSquared` was still a componentwise `v.X*v.X + v.Y*v.Y + v.Z*v.Z` at 11 sites (9 in `GetNextNormal`, 2 in the first-normal specialization), and `CylinderSupportScalar` computed its horizontal length the same way. - **RULE CORRECTION — .NET 10 `Vector.Min/Max` are IEEE minimum/maximum, not `(a OP b) ? a : b`.** The `minmaxprobe` mode establishes that on this runtime `Vector.Max(+0,-0) = Vector.Max(-0,+0) = +0`, `Vector.Min(±0,∓0) = -0`, and NaNs propagate from either operand — bitwise identical to `MathF.Max/MathF.Min` in every probed case (payloads included), while `float.MaxNative/MinNative` keep the old maxss-style second-operand semantics. Reading of the initial data:

- The trivially vectorizable sphere-sphere kernel gets close-to-ideal AoSoA scaling when hot in cache (~6.5x of the theoretical 8x), collapsing toward memory-bandwidth-limited ~2.7x when streaming.
- Box-box — a heavy tester with per-lane scalar fallbacks (`ManifoldCandidateHelper.AddCandidate`'s emulated scatter), lane divergence, and big wide structs — only gets **~2x** from AoSoA against a *bitwise-faithful* scalar transliteration. A scalar-specialized implementation (branchy early-outs, `Vector3`/128-bit SIMD tricks, skipping work the wide form must do for all lanes) would narrow that further; that is the next thing this harness can measure by relaxing the bitwise-equality requirement behind a flag.
- **Cylinder-cylinder gets the best AoSoA scaling of the heavy testers (~2.5x contact-heavy), despite being DepthRefiner-driven.** Its refiner loop, analytic supports, and contact generation are all genuinely wide across pairs; the cross-pair costs (slowest-lane convergence in the refiner, branch-union across contact generator cases) turn out to be modest when supports are cheap vector math. Combined with the hull result, the pattern is clear: AoSoA's value tracks *the fraction of the algorithm that stays wide*, not tester weight or iteration count. The DepthRefiner itself is not the AoSoA bottleneck — per-lane serial support/contact work is.
- **Sphere-box and sphere-cylinder sit at ~9–11x AoSoA speedup against the best-known scalar — at or slightly above the 8-lane ceiling — and that is genuine.** Verified free of harness artifacts: `Test` is confirmed inlined at tier1 (JitDisasm), 4-way accumulator splitting changed nothing, and both branchy and branchless scalar forms were measured (see below). The mechanism was pinned down by a falsification experiment (`benchpipe`): a hand-interleaved two-pair version of the scalar tester (statement-granularity software pipelining, bitwise-identical outputs) ran at **0.98x — no change** — proving the out-of-order core already overlaps consecutive pair iterations and the scalar path is *throughput*-bound, not latency-bound. The throughput limiter is instruction count: the JIT emits ~2KB (~400–500 instructions) per scalar pair versus the ~130-op ideal dataflow — register spills (16 xmm registers against ~40 live values), `in`/`out` struct ABI traffic, and address math — retiring at a healthy ~4–5 IPC ≈ ~100 cycles/pair. The wide version emits a similar-sized instruction stream but retires **eight pairs per stream**: AoSoA's super-linear win on small kernels is *instruction-count amortization* (spills and copies paid per bundle, not per pair).
- **The diagnosis was verified by building the mitigation: `SphereBoxScalarTesterPacked`** packs each Vector3 into one `Vector128` register (in-register 3x3 transpose for the by-transposed transform, ordered horizontal dot, `vminps/vmaxps` clamps, cold predictable branch for the sphere-inside-box case; per-lane operation order preserved → bitwise identical, fuzz-verified over 2.8M lanes). Emitted code collapsed from **~1.6–2KB to ~275 bytes per pair** (tier1: 8099 → 6551 → 1098 bytes for the loop kernels), and time from 17.4–27 ns to **7.2–7.4 ns/pair** — 2.4x over the best unpacked scalar, dropping the AoSoA ratio from ~10x to **~3.5–3.8x**. The residual ~3.5x is a sane SIMD ratio: the packed form still wastes a lane, pays shuffle/horizontal overhead, and processes one pair per sqrt/divide. Corollary: register-packing is the single biggest lever for a competitive AoS baseline on small testers, and likely narrows the mid-size (box-box, cylinder-cylinder) scalar gaps too — their `ScalarMath` Vector3s have the same three-scalars-per-vector pressure problem.
- **Branch-vs-branchless selects: predictable branches beat bitmask selects on the tiny testers by 30–40%** (branchy scalar sphere-box 20.4 vs 29.3 ns; sphere-cylinder 16.3 vs 26.3 — the bitmask select's xmm↔gpr domain crossings land on the critical output chain). On box-box the effect is ~10% the other way's magnitude (branchy ~2.2x vs branchless ~2.4x contact-heavy ratio); cylinder-cylinder is insensitive. Branchy twins (`SphereBoxScalarTesterBranchy`, `SphereCylinderScalarTesterBranchy` — the original fuzz-validated transliterations) are benchmarked alongside the branchless defaults; quote the best-known scalar as the AoS baseline.
- **Where refiner-based testers spend their time (from `stats` mode, avg support iterations per refiner call, contact-heavy):** sphere-hull **2.55**, hull-hull **4.7**, cylinder-cylinder **11.3**. Two distinct cost regimes: cylinder-cylinder is iteration-bound (smooth surfaces converge slowly; cheap supports) — the prime target for warmstarting/better search; sphere-hull is *per-support-call* bound (~3.5 sweeps/pair at ~75ns each when the actual dot products are ~12 cycles) — the cost is the horizontal reduce's variable-index `Vector<T>` element extraction in `ComputeLocalSupport`, the same hotspot the library's own TODO comment flags. Fixing that horizontal phase would compress sphere-hull (and hull-hull) on both representations.
- **Hull-hull AoSoA sits in a ~0.87–1.17x parity band with scalar AoS across hull sizes, select strategies, and JIT modes** — earlier branchy-scalar sessions had AoS winning outright for large hulls (~0.87–0.91x); the branchless-scalar clean-machine session lands at exact parity (1.00x) for large hulls and ~1.1x for small. The structure explains it: even the "wide" tester computes hull supports serially per lane (each lane broadcasts its direction and sweeps its own hull's point bundles — SIMD is *within* the shape, across hull points), and the entire contact-generation phase is per-slot scalar. The only work AoSoA actually amortizes across pairs is the DepthRefiner's simplex/tootbird bookkeeping — and it pays for that with full-bundle simplex math running until the *slowest lane* converges, per-lane `Rebroadcast`/`ReadSlot` extraction on every support call, and dead-lane overhead. As hulls grow, the per-lane support sweeps dominate and the shared bookkeeping (the only AoSoA win) shrinks to noise, so the scalar path's lighter per-iteration loop wins outright (~10–15% for 40–64 point hulls). Hull-hull is also 10–20x more expensive per pair than box-box (~1–3µs), so this parity applies to a large share of narrowphase time in hull-heavy scenes.

## Relaxed-equality hull-hull experiments

A 2026-08-15 study: how much of the engine's wide hull-hull cost is an artifact of the algorithm rather than the representation, measured by building non-bitwise scalar candidates (topology-accelerated supports, full SAT, local axis-space search) and judging them by a tolerance comparator against the engine wide tester plus interleaved throughput ratios. Sections: shared infrastructure, baseline size scan, one subsection per track, and a final cross-comparison with the authoritative same-session numbers.

### Shared infrastructure

### Track 1 — warm-started adjacency-hillclimb hull supports (`hillclimb` / `hillclimbcold`, 2026-08-15)

**Approach.** Same algorithm as the frozen scalar tester end to end (same setup, same `ScalarDepthRefiner`, same `PickRepresentativeFace`/clip/`Reduce`, shared via the `internal` frozen helpers), except the hull support function's O(V) bundle scan is replaced by a greedy walk over the precomputed CSR vertex adjacency: start at a cached vertex (per-pair warm start slot, one per hull, seeded at vertex 0), move to any strictly-better neighbor of the current best until a local maximum of `dot(vertex, direction)` — which on a convex polytope is a global maximum (for any non-maximal vertex, the tangent cone spans R³, so some edge strictly improves). Strict improvement makes each vertex winnable at most once, so termination is provable without the (still present, belt-and-suspenders) round cap. New files: `HillclimbSupport.cs` (`HillclimbHull` shape adapter carrying the topology + a pointer to the tester's stack-local warm slot; `HullSupportScalarHillclimb`, `HullSupportScalarHillclimbCold` as parallel `IScalarSupportFinder`s — `HullSupportScalar` untouched), `HillclimbRelaxedTester.cs` (candidate reusing the generic refiner via a new instantiation; contact-gen vertex reads come from the topology's scalar arrays — same values as the bundle `ReadSlot`s, and linear indices double as feature ids). The bench harness gained a direct interleaved frozen-vs-candidate head-to-head per candidate (`CandidatesVsFrozen`) because composing candidate-vs-frozen through the wide anchor proved thermally fragile.

**Support correctness in isolation (`climbprobe` mode):** 480k queries per size (16 hulls × 30k directions, alternating small correlated steps and random jumps), climb support dot vs the frozen full scan's: **deficit exactly zero in all 2.4M queries, warm and cold, every size** — the walk never returns a worse support than the scan. Average cost scales ~logarithmically where the scan is linear: warm 7.7/10.0/12.3/15.0/18.6 dots per query at 8/16/32/64/128 verts (cold 10.6/15.3/20.1/27.3/36.5) vs the scan's V dots + a serial 8-lane horizontal reduce per query.

**Tolerance validation (`relaxfuzzhull`, sizes {8,16,32,64,128} × seeds {5,1234} × {mixed, contact-heavy}, ~236k cases per cell, ~4.7M total):** PASS 99.82–99.98%, WARN ≤0.07%, TIE 0.013–0.101%, **FAIL 0.004–0.031%** (typical ~0.01%, size-independent; distribution p50/p99 of normal angle 0/≤7e-8 rad, depth error 0/≤2e-8). The cold variant is the same or slightly cleaner (0.001–0.007% FAIL). Every printed FAIL was triaged; with the probe proving supports never regress, the entire FAIL population is **refiner-trajectory divergence seeded by tie/rounding-level support differences** (the climb reaches a different equal-or-better vertex than the scan's index-ordered tie-break; `Vector3.Dot`'s pairwise rounding vs the bundle scan's is enough), which the chaotic tootbird search amplifies into a different — equally self-consistent — converged normal on hard cases. The evidence is the symmetry: sampled normal-angle FAILs split 51 candidate-better / 55 candidate-worse by true support depth (the comparator's own metric; e.g. one FAIL has candidate support depth 0.4520 vs reference depth 0.4825 — the *candidate* found the deeper minimum), and existence flips split 39 candidate-accepts vs 41 reference-accepts. This is the predicted normal-tie disagreement class, not a candidate defect; a stricter gate would need a mutual-improvement comparison (fail only when the candidate's normal is worse than the reference's by more than the tie tolerance *and* not vice versa). The frozen `fuzz` suite stayed green throughout (29/29 configs, exit 0, seeds 5 and 21).

(4) The bundled SIMD neighbor-gather variant was not built: with warm walks averaging 8–19 dots *total* per query over ~6-neighbor rings, a per-vertex padded gather layout would optimize a component that is no longer the bottleneck; it only becomes interesting if PickRepresentativeFace/clip are fixed and V >> 128.

### Track 2 — full SAT hull-hull with gauss-map edge filtering (`sat` / `satraw`, 2026-08-15)

**Approach.** A Gregorius-style full SAT tester (`SatRelaxedTester.cs`, candidates `sat` and `satraw`), single-pair horizontal SIMD over the precomputed `HullTopology` SoA layouts. Phases, all in B-local space with the B→A normal convention: (0) *prepass* — the center-to-center direction's interval depth via two bundled support scans; any direction's depth upper-bounds the true minimum, so `depth < -margin` on ANY axis is a rejection certificate (this axis alone eliminates most far misses for two scans); (1) *face axes of B* — per face, depth = true face support offset − dot(offset, n) + bundled `Vector<float>` max-dot scan over A's padded SoA vertices (`Vector.MaxNative` accumulate + shuffle-reduce horizontal max); (2) *face axes of A*, symmetric (per-face `Matrix3x3.Transform` into B space, scan B's vertices); (3) *edge-edge axes*: for each A edge (direction + both adjacent face normals transformed once), all B edges tested in `Vector<float>` bundles against the arc-intersection (Minkowski face) conditions `t1·t2<0 ∧ t3·t4<0 ∧ t1·t4<0` where `t1=b1·dA, t2=b2·dA, t3=a1·dB, t4=a2·dB` — the cross-product-free formulation, valid because the topology guarantees `edgeDir ∝ +cross(nFace0, nFace1)`; the cheap condition (6 loads) runs first and a movemask short-circuits the bundle; surviving lanes iterate by trailing-zero bits. Survivors use a **sqrt-free improvement test** (compare `raw = depth·|axis|` against `bestDepth²·lenSq` with sign analysis); only actual improvers get normalized and — because the edge-point depth shortcut assumes exact supports — an **exact two-scan interval rescan** before they can steer the winner or reject the pair. Penetrating winners (SAT exact) generate the manifold via the frozen `PickRepresentativeFace` (the SAT-winning face used directly for its own hull; support-vertex witnesses for the other) + the frozen-style clip + frozen `Reduce`; edge winners whose clip comes up empty (exact-axis boundary-touch degeneracy) fall back to the classic SAT single contact at the segment-segment closest point. **Separated-within-margin band**: any negative best depth proves separation, and `sat` then routes to the frozen-configuration `ScalarDepthRefiner` (identical seed and support finder as the frozen tester ⇒ identical trajectory ⇒ the band inherits the reference's knife-edge decisions), skipping the remaining SAT phases outright; `satraw` keeps pure SAT end-to-end to quantify that choice. Modes: `relaxtriagehull` (FAIL-classifying triage with independent `SupportDepth` certificate verification), `satstats` (filter/winner/reject statistics).

**Precompute/infrastructure findings (fixes in `HullTopology.cs`, load-bearing for any future gauss-map consumer):** (a) `Edge.Face0` was documented as "the face that walks Start→End" but was actually assigned in encounter order — ~half of all edges had swapped arc endpoints, which silently breaks the arc-intersection hemisphere sign (first symptom: 90% bogus edge winners, mass rejects of penetrating pairs). Now normalized via `dot(dir, cross(N0,N1)) > 0`. (b) The engine's bounding-plane `Offset` (pivot vertex · area-averaged normal) **understates the hull's true extent along the face normal** on merged near-coplanar faces (the sized sets' 2% radial jitter makes this up to ~2% of radius); SAT interval math needs the new `FaceSupportOffsets` (true max-dot per face normal, O(F·V) once per hull). Both underestimation sources produce *spurious rejects* — SAT's certificates are only certificates if every axis depth is exact-or-overstated.

**Gauss filter behavior (`satstats`, 50k pairs/cell):** per-edge-pair pass rate **5.31% / 2.16% / 0.97% / 0.47% / 0.23%** at 8/16/32/64/128 verts — survivors scale ~linearly with E (≈17/38/78/154/299 per contact-heavy edge-phase pair) while tested pairs scale as E², i.e. the filter is doing its job and the *filter itself* is the O(E_A·E_B) term. Bundle-level early-out (arc test 1): 82%/78%/61%/45%/33% of bundles pass, so the short-circuit saves ~⅔ of the second-half work at 128. The refiner fallback runs on ~20% (mixed) / ~38% (contact-heavy) of pairs — the generator's speculative margins make the separated-in-margin band large; edge winners are ~50% of penetrating winners on these smooth hull families.

(4) Not built: hillclimb-accelerated support scans inside the face phases (would cut the O(F·V/8) term to O(F·log V) and is the obvious splice of Track 1 into Track 2), and a Minkowski-face-region walk to replace the brute-force O(E²) filter — both only matter if the small-size win were worth chasing, and Track 1 already owns that regime.

### Track 3 — local SAT via axis-space hillclimbing (`walk` / `walk2` + `walkstats` / `walkoracle`, 2026-08-15)

**Approach** (`WalkRelaxedTester.cs`, candidate `walk`): search the SAT axis set *locally* instead of exhaustively (Track 2) and without the refiner's simplex iteration (Track 1). All phases in B-local space with exact interval depths: (0) prepass along the center-to-center axis, both supports evaluated by Track 1's warm-started vertex-adjacency climbs (exact by convexity, O(degree) per query); (1) **face walks**: steepest descent on `depth(n)` over each hull's face-adjacency graph (new `HullTopology` CSRs: face→edge, face→adjacent-face, vertex→incident-face), each face evaluation = precomputed `FaceSupportOffsets` for the own hull + one warm climb on the other hull, start face = most-aligned face incident to the support vertex along the start axis; (2) **restricted edge phase**: candidate edges = edges of faces incident to the support vertices along the incumbent axis (ring-expandable; `walk` = ring 0, `walk2` = ring 1), scalar gauss-arc filtered, sqrt-free improvement test + exact climb-based rescan (all Track 2 machinery), iterated to a fixed point as the axis moves; (3) an **outer restart loop** (≤3 rounds): whenever the A-walk/edge phase improves the axis after B's walk finished, re-walk both hulls around the new incumbent — this is coordinate descent in axis space, and it measurably matters (below); (4) any evaluated axis with `depth < -margin` is a sound rejection certificate at any point; (5) **separated-within-margin band** = `ScalarDepthRefiner` with hillclimb supports (Track 1 configuration, center-direction seed) since SAT axes cannot represent vertex-region distance directions (Track 2 finding); (6) manifold generation = Track 2's clip/`Reduce`/edge-degenerate fallback, with representative faces from the topology in O(degree) — the walk already *knows* the winning face, and the other hull's face is the most-aligned face incident to the support vertex — except on the fallback band, which needs the frozen `PickRepresentativeFace` with the refiner witness (the O(degree) pick emptied the clip on ~0.17% of cases there — all speculative pairs where the support vertex's most-aligned face doesn't project onto the other face; caught by triage as candidate-empty flips with the exact reference axis, and fixed by switching only that band to the frozen picker).

**Quality vs the engine (`relaxfuzzhull`, 250k cases × {mixed, contact-heavy} × seeds {5,1234} × sizes {8,16,32,64,128}, ~4.7M total, seed ranges):**

### Track 4 — direct Minkowski-boundary feature walk, "V-Clip in normal space" (`csowalk` + `csoprobe`/`csostats`/`csooracle`, 2026-08-16)

**Approach** (`CsoWalkRelaxedTester.cs`, candidate `csowalk`): walk the facets of the CSO D = B ⊖ A_placed directly, using the fact that D's boundary facets are exactly the cells of the two hulls' overlaid gauss maps — (faceB, vertexA), (vertexB, faceA), and (edgeB, edgeA with crossing arcs) — and that every facet's outward normal IS the B→A manifold axis with plane offset = the exact SAT depth. All facet adjacency is computed on the fly from each hull's own `HullTopology` (new CSR: `VertexEdges`, edge index per vertex-neighbor entry); the overlay graph is implicit and needs no pose-dependent precompute. Two regimes share the graph:

- **Penetrating** (origin inside D): steepest descent on exact facet plane offsets. State = (axis, cell identity, support-vertex anchors, warm climb slots); per step the candidate moves are the anchors' vertex stars on both hulls (faces incident to either support vertex), **plus — load-bearing — the incumbent face's adjacent faces and its own loop edges** (support ties across a face freeze the anchors, so a vertex-star-only walk cannot traverse a hull's face graph: it measured 95.6% basin hit rate and 0.66 steps/pair until the true facet adjacency was added, 99.2% after), plus the gauss-arc-filtered incident-edge pairs (Track 2's cross-free arc test; ~15–67 pairs/pair vs Track 3's 87–171/round) with the sqrt-free pretest + exact climb rescan. Face-vertex cell validity is maintained by construction (each face axis is coupled with a fresh warm climb on the other hull, so the cell is always a real overlay cell and its offset the exact interval depth); every evaluated axis is therefore a sound reject certificate below −margin. Strict improvement ⇒ termination; local minima expected and measured (`csooracle`).
- **Separated** (any facet offset < 0 is an origin-outside certificate — the only way this regime is entered): the classic point-vs-polytope V-Clip walk on the implicit D, states = facet (3 kinds) / edge (2 kinds: (eB,va), (vB,eA)) / vertex (vB,va). Validity conditions actually used: facet states re-climb the partner support vertex every visit (gauss-membership restoration; makes facet terminals — h < 0 with the origin projection inside the CSO polygon — complete global certificates since D provably lies in the separating halfspace); edge states check the Voronoi cone via the two adjacent-facet inward directions cross(n, d_ccw) (winding conventions validated by the deterministic `csoprobe` mode: FacetB polygons = B loop order CCW around n_fB, FacetA polygons = REVERSED A loop CCW around −R·n_fA, 0 violations) plus arc-crossing EE candidates from the partner vertex's incident edges; edge/vertex terminals additionally verify the partner vertex is the true support along the claimed w-direction normal (a violated membership condition names the feature to move — the V-Clip state machine). Guards, all measured in: distance-based scoring with an absolute epsilon floor (1e-6·scale) against boundary dithering; w-direction normals below 1e-4·scale distance are numerically meaningless → certified-axis answer instead; stalls/caps self-certify the best feature seen (supportDepth(w-dir) == −dist is a complete certificate — most "stalls" are unrecognized terminals) or fall back to the most-negative certified axis; a 6-step non-improvement streak guard ends genuine facet↔edge dithering (a raised iteration cap measurably did NOT — the tail is the facet states' per-visit partner re-climbs shifting the polygons, not truncation). **No refiner anywhere**; the walk's own witnesses feed the frozen banded `PickRepresentativeFace` on the speculative band (Track 3's boundary), topology picks on penetrating winners (the face-cell winner's reference face IS the state — no O(F) scan), Track 2/3's clip/`Reduce`/edge single-contact fallback for contacts.

**What this says about the engine's wide hull-hull tester.** Its known bottleneck — the per-lane serial O(V) hull support sweep with a serial horizontal reduce, run twice per refiner iteration — is exactly what Track 1 removes, and removing it flips the representation question: a *scalar per-pair* tester with precomputed CSR vertex adjacency and warm-started hillclimb supports beats the entire AoSoA bundle apparatus at **every** hull size on this family, by ~25–55%, including the dense-hull contact-heavy regime where AoSoA had its only clear hull-hull win. The refiner algorithm itself is vindicated twice over: as a *local searcher* it beats both exhaustive SAT (Track 2) and discrete axis-space walking (Track 3) at every measured size, and its 1–6% non-minimal deep-penetration normals (Track 2's quality finding, candidate-better:reference-better ≈ 14,300:0) are the only quality cost found. Worth porting into the engine, in order of value: (1) **precomputed vertex adjacency + warm-started hillclimb supports for `ConvexHull`** — helps the existing wide tester directly (each lane's serial sweep becomes an O(log V)-ish walk; every hull pair tester shares it) and is the enabling piece for an eventual scalar hull-hull path; needs a per-shape topology precompute at hull build time (CSR adjacency ≈ a few hundred bytes for typical hulls; the `Edge.Face0` winding contract and true face-support offsets from Track 2 matter if faces/edges are ever consumed); (2) **the empty-clip manifold fallback** — the engine's clip/Reduce can return an empty manifold on pairs its refiner accepted (9–81 per 50k contact-heavy cases here); a segment-closest-point single-contact fallback closes it cheaply; (3) with supports cheapened, the next size-scaling costs are `PickRepresentativeFace`'s O(F) scan and the O(|A|·|B|) clip — a topology-driven face pick is validated for penetrating pairs but must keep the current picker on the speculative band (Track 3's boundary). SAT and axis-walking are not worth porting at these sizes; their reusable residue is the gauss-arc topology machinery and the quality findings.

### Post-refiner polish (Track 4 followup, `polishoracle` / `polishbench`, 2026-08-16)

**Question.** The engine refiner converges to a locally-but-not-globally-minimal axis on ~14–15% of contact-heavy and ~33–41% of mixed penetrating pairs (csooracle). How much of that miss mass can a cheap *post-refiner polish* of the converged axis recover, per unit of new engine infrastructure? Four tiers were measured (`PolishOracle.cs`, mode `polishoracle`; oracle = Track 2's exhaustive SAT with `usePolish: false`; refiner = the frozen configuration, bit-identical to the engine path):

- **P0 (zero new infrastructure)**: evaluate the exact interval depths of the two representative-face normals the engine *already selects for clipping* (frozen `PickRepresentativeFace` with the refiner witness, both hulls); adopt the best improvement. Cost: exactly 4 support evaluations — the face selection is already paid.
- **P0b (still no topology)**: evaluate every face inside the picker's plane-error tolerance band (`1e-3·epsilonScale` of the min error, engine bounding-plane offsets), both hulls.
- **P1 (full Track 1/4 topology)**: one steepest-descent step of Track 4's CSO facet machinery (support-vertex stars + gauss-filtered incident edge pairs) seeded at the refiner axis.
- **Pk**: same descent iterated to its local minimum (cap 64, never hit; step p99 = 2 contact-heavy, 3–5 mixed).

Per cell: 20k penetrating cases (48k–99k generated), sizes {8,16,32,64,128} × {mixed, contact-heavy}, seeds 5 and 1234 quoted as ranges; all depths exact (warm adjacency-climb supports). Logs `polish_s5_a/b.log`, `polish_s1234_a/b.log` in the study scratchpad.

**Miss anatomy — the infrastructure question.** Among refiner misses, the SAT-true axis type is **edge-edge on 56–63% (contact-heavy) / 24–33% (mixed)**; the rest split roughly evenly between face-of-A and face-of-B. That single number caps every face-only polish: **P0 recovers 5.4–7.4% of contact-heavy miss mass (mixed 0.9–1.6%), P0b 20.5–28.5% (mixed 4.4–6.6%)** — P0b's recoveries are >95% face-type; it reaches at most ~2–4% of the edge-type misses (only via band faces adjacent to the true edge). The topology tiers jump the cap: **P1 recovers 60.0–65.6% of contact-heavy misses (mixed 18.4–30.9%)** — i.e. about **two thirds of the engine's contact-heavy misses sit one facet-descent step from its converged axis** ("adjacent"), including roughly half the edge-type misses — and **Pk reaches 79.5–82.8% (mixed 30.3–53.4%)**. The remainder (17–20% contact-heavy, half-to-two-thirds mixed) is distant-basin miss mass that no local polish reaches (consistent with csooracle: even a walk started fresh only reaches 97.3–99.2% contact-heavy / 73.8–84.7% mixed).

**Depth-tier split — the gating question.** Contact-heavy penetrating cases split ~61–71% shallow (satDepth ≤ 0.1·scale), ~11–18% mid (0.1–0.25), ~12–27% deep (> 0.25); per-tier refiner miss rates are 8.4–10.9% / 17.1–21.4% / 21.9–32.8%, so the **miss mass is NOT deep-exclusive: 42–45% of contact-heavy refiner misses are shallow contacts** (mid 14–27%, deep 28–44%). Recovery rates are similar across tiers (Pk fixes ~79–85% of shallow misses and ~76–80% of deep ones), so a deep-only gate (e.g. polish only when refiner depth > 0.1·scale — ~30–39% of penetrating pairs) keeps ~55–58% of the recoverable mass and forfeits the rest; a 0.25 gate keeps ~28–44%. The mitigating fact for shallow contacts: their absolute excess is bounded by the tier (≤ 0.1·scale by definition, mean far lower), so what a shallow-gated polish forfeits is mostly *axis identity* (contact placement/feature stability), not large depth error. Mixed-profile miss mass is 83–92% deep, where only distant basins remain — gating helps nothing there.

P0b: 12.5→16.9 supports (22–34), 6.2→8.4 face evals — plus a second O(F) band pass over work the picker already does. P1: 12.3→15.6 supports (16–21), 9.3→12.9 face evals, 21.7→41.4 gauss tests (36–80). Pk: 20.1→24.7 supports (39–52), 15.7→20.7 face evals, 39.3→70.9 gauss tests (89–178), steps mean 0.56–0.61 p99 2 (mixed tails are heavier: supports p99 53–101, gauss p99 132–359, steps p99 3–5). For calibration, the refiner's own search is ~4.7 iterations ≈ 9.4 support sweeps/pair — so Pk performs *more raw search work than the refiner it polishes*, though its units are cheap climbs (~10–20 dots) rather than O(V) scans. Wall clock (`polishbench`, size 32 contact-heavy, 4096 pairs, axis search only, Pk on every penetrating accept, two runs cooldown 1000/2000): refiner alone min 860–863 ns/pair; +Pk min 1687–2362 ns/pair — **+824–1502 ns/pair, 1.96–2.75x** (thermally noisy session, medians 1.5–1.7x mins; counts are the primary metric). Per polished pair (~40% of pairs) that is ~2.0–3.7 µs of unoptimized descent — this is *not* a rare cold branch; unconditional Pk roughly doubles axis-search cost.

**Sanity.** Adopt-worse violations: **0 in all 20 cells** (descent accepts only improvements, verified). Polished-below-SAT: 0–24 per 20k at sizes 8–32 with max gap ≤ 5e-5·scale (rounding between two exact evaluators), growing to 78–184 per 20k at 64–128 with max gap 3.8e-3·scale — triaged as the **SAT oracle's own axis-set granularity**: its face axes are the engine's *area-averaged merged-face normals*, and on the jittered sized hulls the vertex-set CSO's true facet normals (which the refiner/descent find as arbitrary directions) can dip below the stored-normal minimum by up to the coplanarity-merge error. The polish is being under-credited by that amount, not over-credited. Refiner-rejects-on-SAT-penetrating: 33–98 per 20k, max discrepancy 6.5e-5·scale — near-touch knife edges. Refiner reported-vs-exact depth mismatches ≤ 25 per 20k, tolerance-level. Full bitwise `fuzz` re-run at default 4M count after all changes: exit 0 (`polish_fuzz_gate.log`).

**Verdict — honest and mixed, leaning "P0b if cheap wins are wanted, P1 only if Track 1's topology ships anyway, nothing unconditionally."**
- **P0 is nearly free and nearly worthless** (+0.9pp; 1–7% of miss mass). The faces the picker selects are the ones the refiner's axis already almost agrees with — when the refiner is wrong enough to matter, it is wrong about *which face region it is in*, so evaluating the picked faces' normals rarely helps. Not worth even its four support calls.
- **P0b is the best quality-per-infrastructure ratio**: contact-heavy miss 14–15% → 11–12% (a quarter of miss mass) for ~13–17 support evaluations and one extra pass over the bounding-plane scan the engine already runs — no topology, no new shape data. But it is structurally capped by the axis-type split: it cannot touch the ~60% of contact-heavy miss mass whose true axis is edge-edge.
- **P1 is the discrete jump** (miss → 5.5–6%, two thirds of miss mass) and Pk adds surprisingly little on top (→ 2.8–3.1%; steps p99 = 2, so Pk ≈ P1 + a verification step on most pairs — if the descent machinery is present at all, run it to convergence). But both need the full Track 1/4 topology (CSR adjacency, gauss arcs, face-support offsets) *and* ~1.5–2x the refiner's own search work; as a percentage of full pair cost (axis search + clipping + reduce) unconditional Pk is roughly +40–80%. That is only defensible if the topology already ships for Track 1's hillclimb supports (the strongest independently-motivated port) — polish then reuses it — and even then a gate is wanted.
- **Depth gating is a genuine tradeoff, not a free lunch**: ~43% of contact-heavy polish value lives in shallow contacts, so a deep-only cold branch keeps the machinery out of the common path but forfeits nearly half the hit-rate recovery — acceptable if the goal is bounding *depth error* (shallow misses are small in absolute depth by definition), wrong if the goal is axis/feature stability. Mixed/deep-overlap misses are mostly distant basins that no polish tier reaches; the polish ceiling there is ~74–81% hit rate regardless of budget.

### Warm-start guarantee brainstorm (2026-08-16)

Conceptual synthesis (no code, no benches) of a six-lane brainstorm plus adversarial review on the question: which warm-start schemes for the DepthRefiner admit a robust guarantee of never underperforming the c2c initialization, and what "outperform" should even mean. Everything below is post-adversary — claims that died in review are reported as dead.

**1. The definition.** Three collapses and one lattice.

*Collapse 1 — axis quality and depth bound are one metric.* The refiner's reported depth is always the exact one-eval support depth along the reported axis (the only write is `dot(support, normal)` under the strict-improvement select, ScalarDepthRefiner.cs:606–612). So "final axis quality" is not a separate angular question: excess = reportedDepth − satDepth orders schemes identically with raw reported depth, is decidable per pose with one support eval, and is well-defined where angle comparison is not (depth plateaus). *Collapse 2 — clamp at the discard threshold.* Any output below depthThreshold (= −speculativeMargin − margins) is consumed only as a miss flag, so all sub-threshold outputs are one equivalence class; the right per-pose quality is clamped regret q = max(d_S, θ) − max(d*, θ). Without the clamp, every certificate scheme "loses" to c2c on pairs where c2c would have converged to a more negative depth nobody reads — with it, a one-sweep warm separation certificate is exactly as good as a 12-iteration convergence. *Collapse 3 — cost is support sweeps, accounted per bundle.* Sweeps are the latency unit (~9.4/pair hull-hull). Per-lane accounting is fiction in the wide path: the bundle pays max-over-lanes, so a "+1 sweep only on lane X" is +1 wide evaluation for the bundle, and "−(k−1) on certified lanes" materializes only when every lane certifies. All cost claims below are stated with that caveat.

The lattice of "outperforms c2c", strongest to weakest, with achievability attached:

- **Q1 — pointwise clamped-depth dominance**: q_S ≤ q_c2c on *every* pose and warm history, including adversarially stale warm data. Achievable — but *only* by schemes whose reported result is a min over a superset of the exact samples the vanilla c2c run takes (evaluate-and-min-compose). Corollary proved three independent ways: Q1 forces *additive* sweep cost; no Q1 scheme can be pointwise cheaper on penetrating pairs.
- **Q2 — distributional dominance**: first-order stochastic dominance of the clamped-regret distribution under a stated workload. This is where trajectory seeding lives at best. Critical repair from review: warm input is *endogenous* (frame t's warm data is the scheme's own frame t−1 output), so i.i.d.-pose harness cells with synthesized warm inputs do not sample the distribution the scheme actually induces; Q2 certification requires closed-loop multi-frame simulation, and per-frame regret CDFs can hide persistent wrong-normal attractors on stacks.
- **Q3 — expected sweep reduction at pinned quality tier**: meaningful only with a Q-tier held fixed; a scheme may not trade quality for iterations and claim dominance. Provable in exactly one regime (the certified-separated band, below); everywhere else empirical.
- **Lifetime axis (orthogonal, from the temporal lens)**: over a persistent contact, demand the ratchet e_{t+1} ≤ min(e_c2c,t+1, e_t + 2δ_t) (δ = certified pose-delta drift bound) rather than the absorbing trap e_{t+1} ≈ e_t of frozen seeds. Compose-family schemes get the ratchet for free; seeding schemes structurally risk the trap.

Contract costs every warm scheme pays regardless of tier, surfaced by multiple adversaries: (a) per-pose determinism becomes per-history determinism (same pose, different previous frame, different result) — an API-contract change, not a bug, but it must be declared; (b) disposition flips must only ever be toward the *correct* side (all surviving schemes satisfy this — a fired certificate is sound for any axis); (c) **witness validity is a genuine fourth axis the depth metric is blind to**: hull manifold generation reconstructs closestOnA = witness − normal·depth and PickRepresentativeFace selects primarily by witness plane error (ConvexHullPairTester.cs:57–62, ConvexHullTestHelper.cs:29–47), and that reconstruction is valid only when the CSO support is colinear with the normal — which natural termination provides and a raw adopted candidate sample does not. Depth dominance with a corrupted witness is not a shippable win; every tier-A scheme below has to answer for it.

**2. Ranked schemes** (duplicates merged across lanes; each lens independently reinvented the same champion, which is itself evidence).

**Tier A — unconditional Q1 dominance by construction.** Shared invariant: the c2c trajectory runs bit-identically (nothing warm ever touches bestNormal/bestDepth, the simplex, or searchTarget at :276 — the quench coupling is structurally unreachable), and the reported (axis, depth) is the min over {c2c's exact samples} ∪ {extra exactly-evaluated candidates}. Min over a superset ≤ min over the subset; that is the whole proof, and it is the mechanism the polish study validated externally (adopt-worse = 0 across all 20 cells).

- **A1. Warm-axis certificate + output min-compose ("evaluate, never seed").** Proposed independently by all six lanes; the merged form: one support eval along last frame's axis w before the loop. If depth_w < depthThreshold → terminate, separation certified (sound for any axis; this is today's initialNormal pre-check with the trapping failure mode amputated). On failure, w is *discarded from the trajectory*; the vanilla c2c refiner runs; at exit report argmin{c2c output, (w, depth_w)}, comparing pre-margin-re-add. Guarantee: Q1, unconditional over staleness — a garbage warm axis costs one wasted sweep and changes nothing. Lifetime: the ratchet holds; any ancestral frame that found the good basin locks it in at 2δ/frame decay. Cost: +1 sweep on penetrating pairs (~10%), 1 sweep total on warm-certified separated pairs. Surviving attacks, all at the edges, none at the core: (i) witness — when w wins, the single-support witness lacks colinearity and is *not* drop-in for hull pairs; fix by feeding the adopted axis through the normal manifold path or via A2's polish leg; (ii) hygiene is mandatory, not optional — the compose must be LessThan+ConditionalSelect (NaN-safe, .NET10 Vector.Min propagates NaN), the cached axis needs a zero/NaN/renormalize guard (a zeroed slot otherwise "wins" every pair at claimed depth 0 with a garbage normal); (iii) plumbing — no per-pair warm channel exists (PairCache stores constraint handles + clip feature ids only; testers are stateless), so a new 12-byte channel + wide per-lane gather is real work; (iv) the w sample must not perturb the hillclimb support cache's warm slot ahead of the c2c run (isolate or order it); (v) benefit is hysteresis-shaped: it *preserves* good axes across deepening, it does not *find* them — contacts born deep-trapped get nothing; (vi) certificate rejects can diverge from what a same-frame trapped c2c would accept — sound, an improvement, but a declared behavior change. Empirical needs: certificate hit rate and bundle-granularity cost on real scene mixes; closed-loop ratchet measurement (see §4).
- **A2. Warm epilogue / adopt-and-polish.** A1 plus: when the warm sample (or any candidate) beats the snapshot, seed a K-iteration polish leg from the *adopted* axis with a fresh single-vertex simplex, keeping the A1 min as a floor. Trapping is a failure of exploration; the polish leg is not exploring — it starts inside a basin proven better by exact evaluation, where the quench is exactly what you want. Guarantee: Q1 floor unchanged, plus a *valid witness* whenever the leg terminates naturally (termination implies support-normal colinearity — this, per the adversary, is the scheme's real advantage over A1, more than depth). Surviving attacks: on flat-face polytope contacts the seeded vertex-case first normal tilts ~90° off the face (the ×4 push at :588–593 with a corner-tied support), so the leg spends its budget rediscovering the face it was handed — K must be ≥ ~4, and depth gain beyond A1 is second-order O(pose-delta·scale) there; the leg is honestly a witness/simplex repair mechanism on polytope faces and a real refiner on smooth hulls. Wide path: any lane gating costs the bundle K masked iterations. Cost: +1 always, +K on the adoption-triggered subset only (the c2c-miss population the warm axis catches). Empirical: per-tier SAT-oracle excess with/without the leg; K sweep; witness-colinearity residuals.
- **A3. Race-and-compose (capped warm leg + full c2c leg).** Both trajectories, min over both sample sets. Q1 over c2c *and* over the m-capped warm arm (not over uncapped pure-warm — the cap must be stated in the comparand); worst case c2c + k_max + 1. Adversary's decisive point: on coherent face contacts the warm leg runs to its cap (face rediscovery again), so expected cost is ~+k_max, not +1..3; and wide-path divergence doubles. Verdict: correct and useful as an *offline* upper-envelope oracle and win-mining tool, not a shipping path.

**Tier B — conditional guarantees (precondition stated, checker stated).**

- **B1. Regime-gated seeding at the convexity boundary.** Seed the trajectory with the (validated, normalized) warm axis iff its one-sweep depth is negative — checked by the scheme itself with the sweep A1 already pays. When the gate passes, bestDepth is negative and monotone, so max(0, bestDepth) pins searchTarget at the *origin* for the whole run: the quench coupling is off, the separated landscape is geodesically quasi-convex, and — the review's nicest positive theorem — every epsilon-terminated run returns depth within convergenceThreshold of the true distance *seed-independently* (simplex ⊆ CSO bounds distance-to-origin from above by any termination site's measure, while |bestDepth| bounds it from below). Penetrating band falls through to A1 semantics. Residual with no bound either way: iteration-cap (25) exits — expected rare, must be counted, and "worst-case" is where "expected rare" doesn't count. Iteration savings in the band are distributional only (no monotone coupling between seed quality and simplex step count). This weakens the "never seed" slogan to: **never seed while the depth bound is positive.**
- **B2. Zero-eval δ-slack temporal rejection.** Store last frame's (axis A-local, exact depth, relative pose); reject with zero sweeps when d_t + δ < depthThreshold, δ = 2·r_B·sin(Δθ/2) + |ΔoffsetB|. Soundness is unconditional (Lipschitz bound on an exact sample). The adversary gutted the payoff, not the proof: the pipeline stores minimal slack — the loop breaks the instant it clears threshold (:613–614) and separated epsilon loosening understates separation — so on the target population the test mostly fails, and the guaranteed win shrinks to ~1 sweep + dispatch on pairs the pre-loop c2c sample would reject anyway. Recovering multi-sweep savings requires deliberately overshooting on the miss path (extra cost on every miss) and a new keyed temporal cache for pairs the engine currently keeps no state for. Precondition: stored slack exceeds accumulated drift; checker: a dozen flops at narrowphase entry.
- **B3. Warm feature-pair re-derivation.** Carry the winning *feature identity* (face/edge ids), re-derive its axis exactly at the current pose, min-compose per A1. Strictly stronger carry than the raw axis — drift along the carried feature vanishes (e = 0 while the argmax feature persists) instead of decaying at 2δ/frame. Conditions the adversary imposed: polytopes only (cylinder/capsule feature continua break it); correct feature extraction from the terminal simplex every frame (ambiguous at support ties — exactly the measured 1-in-10k rerouting class); near-parallel edge-edge re-derivation must be guarded (unbounded angular sensitivity of normalize(cross)) with fallback to the raw-axis carry; the g/2 validity-radius analysis is optimistic (moving-axis Lipschitz constant) and g is not computable online. The min-compose floor is unconditional; the zero-excess claim is what's conditional. Largest implementation surface in the study (index plumbing does not exist in the wide refiner).

**Tier C — heuristics with no guarantee (stated plainly), and the dead.**

- **C1. Amortized descent (one facet-descent step per frame through the warm carry).** Per-frame Q1 floor holds (compose family). Everything else is a knob, not a guarantee: one step is O(feature degree), unbounded on merged faces without a cap D; the k-frames-to-local-min bound requires an extraction oracle; drift can cycle features indefinitely. Its unique virtue: it is the *only* scheme that breaks the static-pose deterministic-repeat trap (c2c misses are pose-correlated, so min(e_c2c, ·) may never refresh; this advances anyway). Gate it to pairs with miss-risk evidence; polytopes only.
- **C2. Absolute-gate warm seeding** (adopt seed iff depth_w ≤ G). Per-frame depth loss ≤ G is real, but the adversary found an absorbing-state feedback loop: the gated output becomes next frame's warm axis, a trapped axis's depth stays ≤ G in resting contact, so a ~40°-wrong normal at compliant depth is re-adopted *forever* — depth-bounded, normal-unbounded, friction/placement/torque wrong every frame; plus a sep→pen flip mode that persistently injects energy. Only viable with forced periodic decorrelation (every N frames run the c2c path and compose) and G at tolerance scale (~1e-3). The companion negative survives unconditionally: **multiplicative trust gates (adopt iff d_warm ≤ T·d_c2c) guarantee nothing for any T** — achievable loss scales with d_warm absolutely, never the ratio.
- **C3. Bound-preserving warm vertex** (extra simplex vertex, bound untouched): floor only; measured tie-perturbation symmetry (51 better / 55 worse) makes distributional null the expected outcome; on the common coherent case it degenerates to a no-op that still paid its sweep. Exists to be falsified cheaply; expected to lose to A1.
- **Dead on review** (kept as negative results): *warm-direction/cold-magnitude seeding* — the composite target is a fictitious point; simplex planes can pass within epsilon of it and "converge" at iteration ~3 with zero refinement; repairs turn it into a schedule scheme. *Aperture-floor decay schedules* — the majorization claim is false (c2c's magnitude is constant across non-improving iterations, decaying floors dip below it) and the +k cost cap is false (phase-2 length is chaotic in state); only the frozen-floor variant survives, weakly. *V-Clip Voronoi certificates on engine hulls* — merged-face bounding planes understate extent by up to ~2%·radius, so a certificate-PASS can emit a wrong "exact" depth; the vertex-exact repair needs per-visit support climbs, i.e. collapses into Track 4 machinery that cold-start already lost to the refiner. *Reheated warm seed* — an additive heat term H_i blocks every epsilon-termination site while H_i ≥ epsilon, forcing ~13–17 iterations vs the measured 4.7 average; the (H_0, r) window that is hot enough to escape basins and cool enough to terminate is empty. *Terminal-simplex point resurrection* — stale re-transformed points are interior CSO points; termination tests (and, worse, the final witness blend even at the iteration-cap exit) consume them unsoundly; the direction-resampled repair is geometrically degenerate (terminal normals are near-parallel), collapsing its value to a 1-sample floor at 3-sample cost.

**3. Impossibility — where the ceiling is.**

1. **Penetrating-regime seeding impossibility (regime-split form).** While the depth bound is positive, no gate computable from pose deltas, shape radii, last-frame outputs, and any O(1) current-frame support probes can make trajectory seeding satisfy pointwise dominance, even up to tolerance slack. Mechanism: best couples into the trajectory at *four* sites (searchTarget :276, termination-epsilon loosening :277, triangle calibration :375–377, push select :509), so tightening it at t=0 quenches the annealing schedule (the bound's decay schedule IS the exploration schedule) and adds an early-termination mode; δ bounds depth drift uniformly over axes but says nothing about basin membership; the refiner emits no runner-up gap, so distinguishing e_t = 0 from e_t = 1×scale needs the oracle whose absence motivated warm-starting. Maximal coherence maximizes the harm (the trapped axis is re-seeded to itself). Exemptions, precisely: the certified-separated regime (B1's theorem) and provably unimodal landscapes (sphere-like pairs).
2. **Q1 ⇔ superset sampling ⇔ additive cost** (for refiner-based schemes). Constructive shared-budget counterexample: after a teleport the stored warm axis can bitwise equal the c2c direction, making any j ≥ 1 diverted evals exact duplicates of the c2c prefix while the forfeited tail iterations contained the improvement (convergence tails to the 25-cap exist empirically). The only class outside the dichotomy is exhaustive enumeration (full SAT; box-box's 21 axes) — dominance with zero c2c samples, competitive only for small polytopes.
3. **Non-monotonicity, twice.** A better initial depth does not imply a better final depth (jump discontinuities in the sign-test routing; also trivially via the certificate path). And the iteration is not monotone in added *simplex information* either: valid boundary-sample seeds perturb outcomes ~50/50 (measured 51/55 on tie-level substitutions) — a constructed minimal counterexample is still owed to make the second theorem airtight, but no trajectory argument can carry a guarantee.
4. **k-eval regret floor, repaired.** The asymptotic constant-regret impossibility claimed in brainstorm is *false* (a Lipschitz t-net achieves ~scale·k^(−1/2)); what survives is Ω(scale/k) worst-case regret at budget k — which at the engine's k ≈ 9–10 is still a non-negligible fraction of scale. Consequence intact: at practical budgets, no scheme of any kind can promise near-SAT-optimality; all honest guarantees are relative to a baseline or distributional under a workload.
5. **Endogeneity.** Warm state is produced by the scheme it feeds. I.i.d.-pose certification is structurally insufficient for any Q2 claim; hysteresis cuts both ways (compose schemes ratchet good axes in; gated seeds ratchet wrong normals in), and per-frame regret CDFs understate correlated-across-frames failure. Closed-loop sequence evaluation is load-bearing evidence, not garnish.

**4. Recommendation.** Carry three things forward; note the harness gap first: the study has an SAT oracle, tolerance comparator, and scalar refiner mirror, but **no temporally-coherent pose-sequence generator — building one is the prerequisite for every experiment below that involves warm state**, because of impossibility 5. It needs at minimum: persistent resting stacks (near-zero δ), slow slides across face-flip ridges (small δ, basin changes — the adversary's canonical A1/C2 killer), deepening persistent overlap, and teleports; warm state must evolve closed-loop under the scheme being tested.

- **Carry 1: A1 (certificate + min-compose), the ship-path candidate.** Guarantee already proven structurally; experiments certify the implementation and size the benefit. (a) *Dominance fuzz* (exists today, no generator needed): per pose, run vanilla c2c and A1 side by side in the scalar mirror with synthesized warm axes (previous-output, perturbed, garbage, NaN, zero, non-unit); assert reported clamped depth ≤ c2c's on every case and bitwise equality whenever the compose is a no-op — expected violations: exactly 0, any nonzero is an implementation bug (select-vs-Min, margin ordering, guard). (b) *Benefit/ratchet* (needs the generator): frame sequences on stacks and ridge slides, measuring e_t dwell time above tolerance and miss persistence, A1 vs pure c2c — the claim to validate is the ratchet inequality and the hysteresis-shaped win on the 9–32% miss mass; also count certificate fire rate and bundle-granularity sweep cost.
- **Carry 2: A2 (K≈4 epilogue) as the witness-consistency upgrade to A1.** Experiment: same oracle cells as the polish study, arms {c2c, A1, A1+epilogue(K∈{2,4,6})}, reporting per-tier excess *and* witness-colinearity residual (the quantity that makes the hull manifold reconstruction valid) — the depth delta over A1 is predicted second-order on polytope faces and real on smooth hulls; the witness repair is the point. Wide-path bundle cost of masked K-legs must be measured, not assumed.
- **Carry 3: B1 (separated-band seeding).** No quality experiment needed — the seed-invariance theorem covers epsilon exits; measure only (a) iteration-count histograms warm-seeded vs c2c across the separated band (the entire value proposition is this histogram) and (b) the iteration-cap-exit rate under seeding (the residual with no bound). Runs on i.i.d. poses with a synthetic "last-frame" axis since the guarantee is per-frame; the generator only sharpens the realism of the savings estimate.

One closing calibration from the polish section above: min-composing candidates attacks at most the *adjacent + warm-reachable* miss mass; the distant-basin remainder (~17–20% of contact-heavy miss mass, half-to-two-thirds mixed) is provably beyond every local and every warm scheme here, and only enumeration (SAT for small feature counts) reaches it. That is the honest ceiling of this entire design space.

**Implementation notes — the guards that were actually load-bearing.** (1) Axis validation must be NaN-*rejecting by construction*: `!(lengthSquared > 1e-16f) || !IsFinite(lengthSquared)` kills NaN, zero, subnormal-tiny, and overflow-to-inf axes in one shape; finite non-unit axes are renormalized (a garbage-but-finite direction is still a sound certificate probe). (2) The compose is an explicit `<` compare+select — on the one path where a NaN could still appear it loses the comparison and c2c's result passes through untouched; no Min/Max intrinsic anywhere in the compose. (3) The warm-axis evaluation uses its own fresh climb state (starts at vertex 0, never written back), so the subsequent c2c run is bit-identical to a standalone run — this is what the dominance fuzz's bitwise no-op check certifies. A pleasant consequence of the fresh-slot determinism: a B1 seeded run's *initial* refiner sample recomputes the warm sample exactly, so the seeded run's own running min already contains depth_w and the belt-and-suspenders composes never fire beyond rounding. (4) Warm state carries between frames in world space and rotates into the current frame's B-local space at entry (two extra 3x3 transforms per warm frame — included in all wall-clock numbers).

**Verdicts.**
- **A1: yes — the ship-path claim survives implementation.** The Q1 guarantee certified exactly (0 violations in 2.4M adversarial cases + ~1.6M closed-loop frames including teleports), the guards are four lines of code, the cost is +1 sweep on penetrating pairs (self-refunding on separated bands), and the closed-loop benefit is real (15–50% relative dwell reduction, up to 8x mean-excess reduction, strongest exactly where c2c's failure is worst — persistent deepening contact). What it does not do: help contacts born in a bad basin (fewer-but-longer miss runs), or anything at all without a correlated warm channel — the 12-byte-per-pair plumbing (which does not exist in the engine's PairCache today) is the entire price of admission, and this study says it buys a strict-dominance improvement, not a gamble.
- **A2: mandatory rider, not optional upgrade.** Its depth contribution over A1 is second-order at K2 (as the brainstorm's flat-face analysis predicted) and only substantial at K6 on smooth hulls — but that was never the point: A1's raw adopted witness is off by up to *multiples of the pair scale*, which would corrupt the hull manifold reconstruction outright, and the K6 epilogue repairs it by 30–1000x at a cost confined to the ~9–34% adoption subset. If A1 ships for witness-consuming pairs, ship it with the epilogue (K≈6) or route adopted axes through some other witness-producing path; there is no safe raw-adoption configuration.
- **B1: marginal — plumb it only as a free rider on A1.** The seed-invariance theorem holds to ~1e-6·scale and the cap residual shrinks rather than grows, so the risk is genuinely low; but the payoff is ~30% of band sweeps *only under real coherence* (≈ −0.4–0.8 sweeps/frame on separated-heavy streams, ~nothing on contact-heavy ones), and it goes slightly negative on decorrelated streams. Since it reuses A1's already-paid sweep and channel, the incremental plumbing is one branch — worth taking if and only if A1 ships; never worth building alone.
